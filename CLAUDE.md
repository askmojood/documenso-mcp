# CLAUDE.md — documenso-mcp

**Company context comes first: read [../mojood-master/CLAUDE.md](../mojood-master/CLAUDE.md) and
[../mojood-master/STATUS.md](../mojood-master/STATUS.md), then this file.** Never add a `Co-Authored-By` line (or
any Claude attribution) to a commit message or a pull request description.

**What's here:** a Mojood Connect demo, built for one company (Documenso, Inc.) to show them their product working
inside Claude. Six tools over Documenso's v2 API; the two that send email (a reminder, a draft) need a confirmation
code (`tools.py`); nothing signs on anyone's behalf. A local Documenso in Docker (`docker/compose.yml` follows
Documenso's production compose, pinned; `scripts/up.sh`, `scripts/reset.sh`) holds the SAMPLE contracts of the
made-up Harbor Trading (`seed.py`, signing states and times set by `docker/backdate.sql`); Mailpit catches every email
on http://localhost:8026. Private until Hammad sends it; public (Apache-2.0) after. Same recipe as `../snipeit-mcp`.

## Commands
```
scripts/reset.sh                         # fresh local Documenso + SAMPLE contracts (Docker via Colima: `colima start`)
uv run --env-file .env documenso-mcp     # http://127.0.0.1:8007/mcp ; add --stdio for Claude Desktop
uv run --env-file .env pytest            # unit tests + live tests against the local Documenso
uvx ruff check --line-length 120 src tests
```

## Rules
- Secrets (`.env`, `docker/.env`, `docker/cert.p12`: the API token, passwords, keys and the signing certificate) are
  generated by `up.sh`, git-ignored, and never printed, copied into docs or chat.
- Everything in the data is SAMPLE and made up; every address is on an `.example` domain, and email never leaves Mailpit.
- A sending tool never acts without its confirmation code; keep the tests in `tests/test_tools.py` passing.
